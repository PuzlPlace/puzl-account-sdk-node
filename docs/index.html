    Leia isto primeiro

    O Puzl Account a um npm install de distância

    O @puzl/account-sdk liga a sua API Node.js ou NestJS ao Puzl Account, o “Entrar com a Puzl”. É o mesmo SDK que os produtos Laravel já usam, agora em TypeScript, e funciona com import ou require.

    🔐

    Login

    Fluxo OIDC com PKCE, tokens, refresh e validação do id_token.

    👤

    API da conta

    Perfil, senha, e-mail, foto, MFA e apps com acesso.

    📬

    Webhooks

    Verifica os eventos que o Puzl Account manda para a sua API.

    Resumo em uma frase

    Você cria um client, chama métodos async e confere has_error no retorno. O SDK não lança exceção quando o Puzl Account falha, então não precisa de try/catch em volta de cada chamada.

    Atalhos

    Instalar · Início rápido · Login · Erros · Testes · Versões

    1. O que é

    É um pacote npm que fala com o Puzl Account por você. Ele resolve três coisas que dão trabalho fazer na mão: montar o login OIDC direito, validar tokens com segurança e conversar com a API da conta.

    1.1 Onde funciona

    Node.js puro. Express, Fastify, Koa, o que for. Basta criar o client.
    NestJS. Tem módulo pronto (PzAccountSdkModule) com injeção pela classe.
    TypeScript. Tipos completos, para qualquer moduleResolution.
    JavaScript puro. require() ou import; não precisa ter TypeScript instalado.

    Node.js 18.17 ou mais novo. Zero dependências de runtime.

    1.2 O que ele não faz

    • Não guarda sessão. Os tokens são do usuário; quem guarda é a sua API (sessão, banco, Redis).
    • Não tenta de novo. Sem retry automático: quem decide a política é o produto.
    • Não roda no navegador. Ele carrega o client_secret, então é só para o backend.

    2. Instalar

    O pacote vem direto do GitHub, pela tag de versão. Não há publicação no npmjs.com. Funciona igual ao composer require dos projetos Laravel.

    1. 1

      Tenha acesso ao repositório

      O repositório é privado. Sua máquina precisa conseguir clonar PuzlPlace/puzl-account-sdk-node, por chave SSH ou token do GitHub. Teste com:

      git ls-remote git@github.com:PuzlPlace/puzl-account-sdk-node.git
    2. 2

      Instale uma vez

      npm install github:PuzlPlace/puzl-account-sdk-node#semver:^1.0.0

      O #semver:^1.0.0 funciona como o ^1.0 do Composer: aceita qualquer 1.x.y e nunca pula para 2.0.0 sozinho.

    3. 3

      Commite o package.json e o package-lock.json

      A dependência fica gravada assim:

      "dependencies": {
  "@puzl/account-sdk": "github:PuzlPlace/puzl-account-sdk-node#semver:^1.0.0"
}

      Daí em diante, quem clonar o projeto roda só npm install. O lock fixa a versão exata, então todo mundo usa a mesma.

    2.1 Acesso fora da sua máquina

    O CI e o build do Docker também clonam o repositório. Escolha um jeito de dar acesso:

    Bom para máquinas de dev que já têm chave SSH no GitHub.

    npm install git+ssh://git@github.com/PuzlPlace/puzl-account-sdk-node.git#semver:^1.0.0

    Um token com leitura do repositório. Configure uma vez por máquina; o package.json continua sem segredo.

    git config --global url."https://${GITHUB_TOKEN}@github.com/".insteadOf "https://github.com/"

    Passe o token como secret do build. Assim ele não fica gravado em nenhuma camada da imagem.

    # Dockerfile
RUN --mount=type=secret,id=gh_token \
    git config --global url."https://$(cat /run/secrets/gh_token)@github.com/".insteadOf "https://github.com/" \
 && npm ci \
 && git config --global --unset url."https://$(cat /run/secrets/gh_token)@github.com/".insteadOf

# build
docker build --secret id=gh_token,env=GITHUB_TOKEN .

    O GITHUB_TOKEN do job só enxerga o próprio repositório. Use um token (PAT ou GitHub App) com leitura deste repo, guardado em um secret.

    - run: git config --global url."https://${{ secrets.PUZL_SDK_TOKEN }}@github.com/".insteadOf "https://github.com/"
- run: npm ci

    ⚠️ Nunca coloque o token no package.json

    Uma URL como https://ghp_xxx@github.com/... vai para o Git e para o lock. Use SSH ou o insteadOf acima.

    3. Configurar

    Peça ao time do Puzl Account o cadastro do seu app (client). Você recebe client_id e client_secret. Coloque tudo no .env:

    PUZL_ACCOUNT_ISSUER=https://accounts.exemplo.test
PUZL_ACCOUNT_CLIENT_ID=meu-produto
PUZL_ACCOUNT_CLIENT_SECRET=***
PUZL_ACCOUNT_REDIRECT_URI=https://api.meu-produto.test/auth/callback
    VariávelPadrãoPara quê
    PUZL_ACCOUNT_ISSUER—URL do Puzl Account, sem barra no final. Precisa bater com o iss dos tokens.
    PUZL_ACCOUNT_CLIENT_ID—Identificador do seu app.
    PUZL_ACCOUNT_CLIENT_SECRET—Senha do seu app. Só fica no servidor.
    PUZL_ACCOUNT_REDIRECT_URI—Para onde o login volta. Precisa estar cadastrada no client.
    PUZL_ACCOUNT_SCOPEopenid email profileAdicione offline_access para receber refresh token.
    PUZL_ACCOUNT_TOKEN_AUTH_METHODclient_secret_postOu client_secret_basic, ou none. Igual ao cadastrado.
    PUZL_ACCOUNT_TIMEOUT10Segundos por requisição.
    PUZL_ACCOUNT_JWKS_CACHE_TTL3600Segundos que as chaves públicas ficam em cache.
    PUZL_ACCOUNT_LEEWAY60Tolerância de relógio, em segundos, na validade dos tokens.

    Cada variável tem uma opção equivalente em camelCase (issuer, clientId, clientSecret…), para quem prefere passar a configuração no código.

    A API sobe mesmo sem configuração

    A configuração só é conferida na primeira chamada. Se faltar algo, a PzAccountSdkConfigurationException diz a variável exata. Para esconder o botão “Entrar com a Puzl” enquanto não está configurado, use puzl.isConfigured(), que nunca lança exceção.

    4. Início rápido

    Crie uma instância do client para a aplicação inteira e reaproveite. Escolha o seu caso:

import { PzAccountSdkClientFactory } from '@puzl/account-sdk';

export const puzl = PzAccountSdkClientFactory.fromEnv(); // lê PUZL_ACCOUNT_*

// em qualquer lugar
const me = await puzl.meShow({ access_token: token });
if (me.has_error) { /* trate a falha */ }
console.log(me.user?.name);
    // app.module.ts
import { PzAccountSdkModule } from '@puzl/account-sdk/nestjs';

@Module({
  imports: [PzAccountSdkModule.forRoot({ isGlobal: true })], // lê PUZL_ACCOUNT_*
})
export class AppModule {}

// auth.service.ts — injeta pela própria classe
import { PzAccountSdkClient } from '@puzl/account-sdk';

@Injectable()

    Como chamar qualquer operação

    Passe um objeto com os campos em snake_case, os mesmos do Puzl Account e do SDK PHP: { access_token }, { code, code_verifier }. Se preferir, passe o DTO (new PzAccountSdkTokenRefreshDto({...})). O retorno é sempre um DTO com has_error.

    5.1 O código completo (Express)

    import { timingSafeEqual } from 'node:crypto';
import { puzl } from './puzl.js';

const safeEqual = (a: string, b: string) =>
  Buffer.byteLength(a) === Buffer.byteLength(b) && timingSafeEqual(Buffer.from(a), Buffer.from(b));

// 1) Início: gera os segredos, guarda NA SESSÃO e manda para a Puzl.
app.get('/auth/login', (req, res) => {
  const pkce = puzl.pkceCreate();
  req.session.puzlLogin = pkce.toArray();
  res.redirect(puzl.authorizeUrl({ state: pkce.state, nonce: pkce.nonce, code_challenge: pkce.code_challenge }));
});

// 2) Callback: confere o state, troca o code e valida o id_token.
app.get('/auth/callback', async (req, res) => {
  const login = req.session.puzlLogin;
  delete req.session.puzlLogin; // uso único

  if (!login || !safeEqual(login.state, String(req.query.state ?? ''))) {
    return res.sendStatus(400);
  }

  const tokens = await puzl.tokenExchangeCode({ code: String(req.query.code), code_verifier: login.code_verifier });
  if (tokens.has_error) return res.redirect('/auth/login'); // code vencido ou já usado

  const identity = await puzl.idTokenVerify({
    id_token: tokens.id_token,
    nonce: login.nonce,
    access_token: tokens.access_token,
  });
  if (identity.has_error) return res.sendStatus(identity.isServiceUnavailable() ? 503 : 401);

  // identity.sub é a chave do usuário no seu banco.
  const user = await users.findOrCreateBySub(identity.sub, { email: identity.email, name: identity.name });
  // ... cria a sessão da sua API
});

    5.2 Os três segredos do login

    CampoPara quêOnde vive
    stateGarante que o callback é do login que esta sessão começou (contra CSRF).Sessão. Conferir no callback.
    nonceAmarra o id_token a esta tentativa.Sessão. Passar ao idTokenVerify.
    code_verifierProva que quem troca o code é quem começou o login (PKCE).Sessão. Nunca vai ao navegador.

    ✅ Certo

    users.findBySub(identity.sub)

    ❌ Errado

    users.findByEmail(identity.email)

    O e-mail muda; o sub não. Só use o e-mail para vincular uma conta existente quando email_verified for true.

    5.3 Variações do fluxo

    • Popup: passe redirect_uri e response_mode: 'web_message' ao authorizeUrl.
    • Abrir no cadastro: prompt: 'create'. Escolher conta: prompt: 'select_account'. Pedir a senha de novo: prompt: 'login'.
    • Pré-preencher o e-mail: login_hint: 'ana@exemplo.com'.
    • Sem sessão de navegador (app mobile): guarde os segredos no cache, por uma chave que só o cliente legítimo tenha. Não use o state como chave, porque ele viaja na URL.

    6. Tokens

    O que você recebe no tokenExchangeCode e o que fazer com cada um.

    TokenO que éUse para
    id_tokenJWT assinado: “esta pessoa é X”.Passe sempre pelo idTokenVerify antes de confiar.
    access_tokenOpaco (não dá para ler). Vale cerca de 1 h.Chamar userInfoShow e a API da conta (me*).
    refresh_tokenSó vem com o escopo offline_access.Renovar com tokenRefresh. Gira a cada uso.
     
    // O access token ainda vale? (401 invalid_token = vencido ou revogado)
const info = await puzl.userInfoShow({ access_token });

// Renovar: guarde SEMPRE o refresh_token novo. Reusar o antigo derruba a família inteira.
const renewed = await puzl.tokenRefresh({ refresh_token });

// Logout de verdade: revoga o refresh (derruba os access tokens dele também).
await puzl.tokenRevoke({ token: refresh_token, token_type_hint: 'refresh_token' });

// Login com e-mail e senha digitados no seu app (precisa de client habilitado).
import { PzAccountSdkIdTokenVerifyDto } from '@puzl/account-sdk';

const tokens = await puzl.tokenPassword({ username: email, password });
const identity = await puzl.idTokenVerify(PzAccountSdkIdTokenVerifyDto.forPasswordGrant(tokens.id_token, tokens.access_token));

    ⚠️ Password grant e MFA

    No tokenPassword, senha errada e conta com MFA chegam iguais, como invalid_grant. Se o usuário tem MFA, mande-o para o fluxo de redirect (seção 5).

    7. Logout e telas da conta

    Ambos só montam uma URL, sem chamada de rede. Mande o navegador para ela.

    import { PzAccountSdkAccountPageEnum } from '@puzl/account-sdk';

// Encerra a sessão na Puzl e volta para o seu app.
res.redirect(puzl.logoutUrl({ id_token_hint: idToken, post_logout_redirect_uri: 'https://app.test/logged-out' }));

// Leva o usuário à tela de trocar senha na Puzl.
res.redirect(puzl.accountUrl(PzAccountSdkAccountPageEnum.PASSWORD));

    Telas disponíveis: HOME, PROFILE, PICTURE, PASSWORD, LOGIN_METHODS, MFA_ENROLL e DELETE.

    O logoutUrl encerra a sessão no provedor, mas não revoga tokens já emitidos. Para isso, use o tokenRevoke.

    8. API da conta

    Operações sobre a conta do usuário, sempre com o access_token dele. Quase todas exigem um app first-party (produto da Puzl); fora disso, retornam FORBIDDEN.

    MétodoEndereçoO que faz
    userRegisterPOST /api/identity/usersCria conta (público, sem token). Não loga.
    meShowGET /api/identity/meConta do dono do token.
    meUpdatePUT /api/identity/meAtualiza o perfil. PUT completo.
    mePasswordChangePUT …/me/passwordTroca a senha (revoga os tokens).
    meEmailChangePOST …/me/emailPede troca de e-mail; confirmada pelo e-mail antigo (202).
    mePictureUpload · mePicturePresetSet · mePictureDelete…/me/picture*Foto da conta.
    meMfaShow · meMfaEnroll · meMfaEnrollConfirm · meMfaDisable · meMfaRecoveryCodesRegenerate…/me/mfa*Autenticação em dois fatores (TOTP).
    meConsentList · meConsentRevoke…/me/consents*Apps com acesso à conta.
    meApplicationListGET …/me/applicationsApps em que o usuário está cadastrado, da Puzl e de terceiros (is_first_party). Não é controle de acesso.

    8.1 Editar o perfil sem apagar nada

    O meUpdate substitui o perfil inteiro: campo opcional vazio apaga o valor na conta. Parta sempre da conta atual:

    import { PzAccountSdkMeUpdateDto } from '@puzl/account-sdk';

const me = await puzl.meShow({ access_token });
if (me.has_error || me.user === null) { /* trate a falha */ }

const result = await puzl.meUpdate(PzAccountSdkMeUpdateDto.fromUser(access_token, me.user, { name: 'Ana Maria' }));

    8.2 Foto

    // Upload vindo do multer (memoryStorage): a extensão do nome define o tipo.
await puzl.mePictureUpload({ access_token, contents: req.file.buffer, filename: req.file.originalname });

// Ou de um arquivo em disco.
await puzl.mePictureUpload(PzAccountSdkMePictureUploadDto.fromPath(access_token, '/tmp/foto.png'));

// Ou uma ilustração pronta.
await puzl.mePicturePresetSet({ access_token, preset: 'rocket' });

    Aceita jpg, png ou webp, até 5 MB. O nome do arquivo é limpo pelo SDK antes de ir para a requisição.

    8.3 Ligar o MFA

    1. meMfaEnroll({ access_token, current_password }) devolve secret, otpauth_uri e qr_svg. Mostre o QR code.
    2. O usuário digita o código do app autenticador: meMfaEnrollConfirm({ access_token, code }).
    3. A resposta traz recovery_codes. Mostre uma vez e não guarde.

    9. Webhooks

    O Puzl Account avisa a sua API quando algo muda na conta. O corpo do POST é um token assinado (application/secevent+jwt); o SDK confere a assinatura e devolve o evento.

    import { PzAccountSdkWebhookEventTypeEnum as Event } from '@puzl/account-sdk';

// O corpo precisa chegar CRU (texto), não como JSON.
app.post('/webhooks/puzl', express.text({ type: 'application/secevent+jwt' }), async (req, res) => {
  const event = await puzl.webhookEventVerify({ token: req.body });

  if (event.has_error) return res.sendStatus(event.isServiceUnavailable() ? 503 : 401);

  // event.txn se repete nas reentregas: use como chave de idempotência.
  switch (event.getEventType()) {
    case Event.TOKENS_REVOKED:
    case Event.ACCOUNT_DISABLED: /* derrubar as sessões de event.sub */ break;
    case Event.ACCOUNT_DELETED:
    case Event.CONSENT_REVOKED:  /* desvincular event.sub */ break;
    case Event.EMAIL_CHANGED:    /* atualizar para event.data.email */ break;
    default: // evento novo: responda 2xx e ignore
  }

  res.sendStatus(202);
});

    No NestJS (Express), registre o parser do tipo do webhook no main.ts e leia o texto em req.body:

    const app = await NestFactory.create<NestExpressApplication>(AppModule);
app.useBodyParser('text', { type: 'application/secevent+jwt' });

// no controller
@Post('webhooks/puzl')
async webhook(@Body() token: string) {
  const event = await this.puzl.webhookEventVerify({ token });
  // ...
}

    10. Tratamento de erro

    Falha do Puzl Account não vira exceção: vem no retorno. Todo retorno tem estes campos:

    Campo / métodoO que diz
    has_errortrue se deu errado. É o primeiro que você olha.
    error_codeCódigo estável, para ramificar (veja abaixo).
    error_messageTexto traduzido. Bom para log; pode mudar sem aviso.
    errorsErros por campo num 422: { email: ['inválido'] }.
    http_statusStatus HTTP da resposta.
    getErrorCode()O código como enum, ou null se for desconhecido.
    isServiceUnavailable()Timeout, falha de conexão ou 5xx.
    isRateLimited()429: espere e tente depois.
    firstFieldError()A primeira mensagem de campo, para mostrar ao usuário.

    10.1 Ramificando

    import { PzAccountSdkErrorCodeEnum as Code } from '@puzl/account-sdk';

const result = await puzl.mePasswordChange({ access_token, current_password, password });

if (result.has_error) {
  if (result.isServiceUnavailable() || result.isRateLimited()) throw new ServiceUnavailableException();

  switch (result.getErrorCode()) {
    case Code.INVALID_CURRENT_PASSWORD: return { field: 'current_password', message: 'Senha atual incorreta.' };
    case Code.VALIDATION_ERROR:         return { message: result.firstFieldError() };
    default:                            throw new InternalServerErrorException(result.error_message); // sempre tenha um default
  }
}

    10.2 De onde vem o código

    API da conta

    Maiúsculas: EMAIL_ALREADY_EXISTS, VALIDATION_ERROR.

    OAuth (/oauth/*)

    Grafia das RFCs: invalid_grant, invalid_client.

    O próprio SDK

    ID_TOKEN_INVALID, WEBHOOK_TOKEN_INVALID, JWKS_UNAVAILABLE.

    Culpa do usuário ou do sistema?

    Use result.getErrorCode()?.isClientFault(). Um invalid_client é erro de configuração do seu app: mostrar “credenciais inválidas” ao usuário derruba quem não tem culpa.

    10.3 Quando há exceção

    Só em erro de integração, que se corrige no código, nunca em falha do provedor:

    • PzAccountSdkConfigurationException: falta configuração (ex.: PUZL_ACCOUNT_CLIENT_SECRET). A mensagem diz o que corrigir.
    • TypeError: uso errado do SDK, como esquecer o nonce no idTokenVerify, preset ou tela que não existe, foto ilegível.

    Nos métodos async, elas chegam como Promise rejeitada; nos locais (authorizeUrl, accountUrl…), na hora.

    11. Testes no seu projeto

    Nos seus testes, troque o client pelo PzAccountSdkClientFake. Nada sai para a rede, e você programa o que cada operação responde.

    import { PzAccountSdkClientFake } from '@puzl/account-sdk/testing';

const puzl = new PzAccountSdkClientFake();
puzl.respondWithError('tokenPassword', 'invalid_grant', 400);
puzl.respond('meShow', { user: { sub: '01J...', name: 'Ana' } });

// ... exercita o seu código com `puzl` no lugar do client real ...

expect(puzl.callCount('tokenPassword')).toBe(1);
expect(puzl.lastInput('tokenPassword')?.username).toBe('ana@e.test'); // já tipado
    import { PzAccountSdkClient } from '@puzl/account-sdk';
import { PzAccountSdkClientFake } from '@puzl/account-sdk/testing';

const puzl = new PzAccountSdkClientFake();
const moduleRef = await Test.createTestingModule({ imports: [AppModule] })
  .overrideProvider(PzAccountSdkClient)
  .useValue(puzl)
  .compile();
    • Sem nada programado, toda operação responde sucesso plausível.
    • Respostas programadas formam uma fila; a última se repete.
    • respond() aceita o DTO, um objeto com os campos ou uma função (inclusive async) da entrada.
    • puzl.configured = false simula a integração desligada.
    • O fake estende o PzAccountSdkClient: passe-o direto onde o seu código pede o client.

    12. import × require × TypeScript

    O pacote é compilado nos dois formatos, cada um com seus tipos. O Node escolhe sozinho o certo. Não há nada para configurar.

    Seu projetoRecebe
    require('@puzl/account-sdk')dist/index.cjs
    import … from '@puzl/account-sdk'dist/index.js
    TypeScript moduleResolution: node (NestJS clássico)tipos por types e typesVersions
    TypeScript node16, nodenext ou bundlertipos por exports (.d.cts ou .d.ts)

    ⚠️ Use um estilo só no projeto

    Misturar import e require do SDK no mesmo processo carrega duas cópias dele. Tudo continua funcionando, menos o NestJS, que não reconhece a classe de uma cópia como token da outra.

    Três pontos de entrada:

    • @puzl/account-sdk: client, DTOs, enums.
    • @puzl/account-sdk/nestjs: PzAccountSdkModule. Só este exige o @nestjs/common instalado.
    • @puzl/account-sdk/testing: o fake, para testes.

    Testado de verdade

    Antes de virar versão, o CI instala o pacote em projetos reais: require e import em Node 18, 20, 22 e 24; TypeScript node10 e nodenext; apps NestJS 10, 11 e 12.

    13. Versões e atualização

    As versões seguem o mesmo esquema do SDK PHP: o que chega em production com CI verde vira versão sozinho.

    BranchO que acontece
    masterDesenvolvimento. Todo push e PR roda os testes.
    productionMerge com CI verde gera a tag vX.Y.Z (patch +1) e a Release no GitHub.
    • Minor ou major: em Actions → Tests → Run workflow, escolha a branch production e o bump.
    • Atualizar um produto: npm update @puzl/account-sdk. Isso respeita o ^, então não pula de major.
    • Trocar de major: edite a faixa no package.json (#semver:^2.0.0) e rode npm install.
    • O que mudou: a página de Releases do repositório tem as notas de cada versão.

    Por que o dist/ não está na branch?

    O build só existe no commit da tag, que o workflow cria na hora da release — o mesmo pacote que o CI testou, sem scripts nem dependências de desenvolvimento. Por isso o npm install baixa o pacote já compilado e não instala nada além dele, e as branches ficam limpas.

    14. Regras de ouro

    🆔

    Identifique a pessoa pelo sub, nunca pelo e-mail

    O sub é permanente; o e-mail muda.

    ✅

    Confira o has_error de toda chamada

    O SDK não lança exceção por falha do provedor. Ignorar o retorno é ignorar o erro.

    🔏

    Nunca confie num id_token sem o idTokenVerify

    E sempre com o nonce da sessão. Decodificar “na mão” não valida a assinatura.

    🔄

    Guarde sempre o refresh token novo

    Reusar o antigo é tratado como roubo e derruba todos os tokens daquela sessão.

    🙈

    Não logue os DTOs de retorno

    Os de entrada saem mascarados (********). Os de retorno carregam tokens de verdade.

    1️⃣

    Um client por aplicação

    Ele guarda em cache as chaves públicas. Criar um por requisição joga o cache fora.

    15. Perguntas frequentes

    Tenho vários pods. O cache das chaves funciona?+

    Funciona: cada pod mantém o próprio cache em memória e busca as chaves uma vez por hora, mesmo com muitos logins ao mesmo tempo. Para dividir entre pods, passe cache com um adaptador de strings:

    const puzl = PzAccountSdkClientFactory.fromEnv(process.env, {
  cache: {
    get: (key) => redis.get(key),
    set: (key, value, ttl) => redis.set(key, value, 'EX', ttl),
    add: async (key, value, ttl) => (await redis.set(key, value, 'EX', ttl, 'NX')) === 'OK',
  },
});
    Uso proxy ou APM no fetch. Dá para trocar o transporte?+

    Sim. Passe a opção fetch ao client: uma função que recebe um Request e devolve a Response.

    O access token é um JWT? Posso ler?+

    Não. Ele é opaco. Para saber quem é o usuário ou se o token ainda vale, chame userInfoShow ou meShow.

    O error_code veio um que não está no enum. E agora?+

    É um código novo do provedor. O getErrorCode() devolve null e a string crua fica em error_code. Trate no default como falha genérica. Uma versão nova do SDK vai conhecê-lo.

    Existe algum SDK para o frontend?+

    Este é só para backend, porque carrega o client_secret. O frontend chama a sua API, e ela usa o SDK.

    É igual ao SDK do Laravel?+

    Mesmas operações, mesmos nomes, mesmos campos e mesmos códigos de erro. As diferenças são de linguagem: os métodos são async, as opções de configuração são em camelCase e o fake é instanciado com new.

    Se você lembrar de só uma coisa

    1. 1. Instale com npm install github:PuzlPlace/puzl-account-sdk-node#semver:^1.0.0 e commite o lock.
    2. 2. Configure os PUZL_ACCOUNT_* e crie um client (fromEnv() ou PzAccountSdkModule).
    3. 3. Login: pkceCreate → authorizeUrl → tokenExchangeCode → idTokenVerify.
    4. 4. Toda chamada: confira has_error; identifique a pessoa pelo sub.
    5. 5. Nos testes, use o PzAccountSdkClientFake.
